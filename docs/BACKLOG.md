# Backlog — отложенные задачи и находки

Сюда складываются вещи, найденные по ходу разработки/тестирования, которые
можно сделать потом. Без приоритетов — просто чтобы не потерять.

## UI / UX
- **Кнопки скачивания** в UI: «Скачать график (PNG)» и «Скачать report.json».
  Сейчас график сохраняется только ПКМ, а JSON открывается в новой вкладке.
- **Абсолютные координаты в операторском режиме**: фича origin (точка старта →
  lat/lon в отчёте/CSV) подключена только в авто-режиме; операторский (RPi) —
  при желании по аналогии.

## Надёжность / прод-готовность
- **Rate-limiter не должен считать read-only поллинг.** Операторский UI поллит
  `GET /missions/{id}/stream/status`, `/alerts`, `/missions/{id}/trajectory`
  несколько раз в секунду. Сейчас лимит выключен в dev и поднят до 600 в cloud,
  но правильнее освободить эти GET-эндпоинты от лимита (по префиксу), чтобы
  держать строгий cap без риска заблокировать собственный UI.
- **Авто-сессия падает целиком при ошибке детектора.** Если `/detect` отвечает
  500 (например, httpx.HTTPStatusError), цикл сессии не ловит это (ловит только
  RuntimeError/ValueError/TypeError) → поток падает → миссия «завершается сразу».
  Захардить: `http_detector` должен транслировать HTTP-ошибки в доменную ошибку,
  либо цикл — логировать и продолжать по кадру.
- **replication_outbox растёт без дренажа в dev** (sync-worker'а нет). Для dev
  норма, но стоит предусмотреть периодическую очистку/ретеншн.

## Модель / NCNN
- **NCNN-пакет назван `_ncnn`, а не `_ncnn_model`** — Ultralytics не распознавал
  формат. Сейчас обходится симлинком в `NcnnYoloDetector`, но артефакт модели
  (и в `runtime/models`, и в реестре на Yandex) лучше переэкспортировать/
  переименовать корректно.
- **NCNN чувствителен к imgsz**: модель корректна только на `imgsz=960` (как в
  экспорте); на 640 выдаёт мусор (вырожденные боксы). Контракт стоит на 960 —
  свериться, что любые новые экспорты совпадают по размеру.
- **NCNN-смоук на реальном RaspberryPi** (`uv sync --extra inference` + один
  `detect()`) — подтвердить работу на железе перед защитой.

## Авто-режим / навигация (найдено при прод-проверке 2026-06-04)
- ~~Развязать throttle детекции от частоты навигации.~~ **СДЕЛАНО 2026-06-04.**
  Источник видеофайла отдаёт КАЖДЫЙ нативный кадр (nav нужна плотность для
  marker-LK); операторский `fps` теперь throttle'ит ТОЛЬКО детектор через
  `detect_fps` → per-frame stride в `AutoSession`
  (`stride = round(source_fps / detect_fps)`).
- **force-complete не останавливает live auto-сессию.** Закрывает миссию в БД,
  но сессия остаётся `running` в менеджере (зависает, UI цепляется к мёртвому
  WS). Force-complete должен звать stop активной auto-сессии этой миссии.
- **Транспорт RPi-стрима нестабилен (RTSP 404).** Дрон публикует RTSP через
  раз; при отказе ~48с ретраев до MJPEG-фолбэка. Варианты: ускорить фолбэк
  (1-2 попытки + socket-timeout) или сделать MJPEG основным транспортом.
