# Доступ к сервису: публичное демо vs контролируемый прод

Удалённый (cloud) сервис может работать в двух режимах доступа. Выбор —
вопрос конфигурации, кода менять не нужно.

## 1. Публичное демо «попробовать любому»

Цель — чтобы любой желающий мог зайти и потыкать систему. Аутентификация
здесь не применяется (она различает «кто ты», а у публичного демо такого
ограничения нет). Вместо неё — лимиты и эфемерность.

Конфигурация:

| Переменная | Значение | Зачем |
|---|---|---|
| `API_AUTH_TOKEN` | **не задавать** (пусто) | Bearer-гейт выключен → токен вводить не нужно |
| `APP_RATE_LIMIT_PER_MIN` | напр. `60` | Кап запросов на IP/мин (защита от флуда) |
| `UPLOAD_MAX_MB` | напр. `200` | Кап размера загружаемого видео/ZIP |

Встроенные ограничители, которые уже есть и работают всегда:

- **Одна активная миссия за раз.** Старт второй сессии отдаёт `409`; UI
  показывает «Система занята другой миссией, попробуйте позже». Это
  естественный предел для открытого демо (один пользователь за раз).
- **Rate limit** считает по `X-Forwarded-For` (реальный клиент за ингрессом),
  отдаёт `429 Retry-After: 60`. Пробы (`/health`, `/metrics`), оболочка UI и
  доки никогда не лимитируются.

Замечание о масштабировании: лимитер — in-process (одна реплика). Для
нескольких реплик вынесите лимит на ингресс (nginx `limit_req`) — это
конфигурация деплоя, в коде ничего менять не надо.

## 2. Контролируемый прод (закрытый доступ)

Цель — пускать только своих. Включается shared-secret bearer-токеном.

1. Сгенерировать токен: `scripts/security/gen_api_token.sh`
   (внутри `openssl rand -hex 32`).
2. Положить в секрет деплоя (Vault / `kubectl create secret`) и пробросить в
   `API_AUTH_TOKEN` пода api.
3. Раздать токен авторизованным операторам **out-of-band** (лично, в
   менеджере паролей). **Самостоятельной регистрации нет by design** — это
   модель общего секрета, а не учётных записей.
4. Оператор вставляет токен в поле «API-токен» в шапке UI (хранится в
   localStorage), после чего все запросы несут `Authorization: Bearer <token>`
   автоматически.

Открытыми остаются только пробы/метрики/доки и оболочка UI (`/`, `/pilot`),
чтобы k8s, Prometheus и браузер могли загрузиться; всё остальное требует токен.

WebSocket-стрим авто-сессии (`/auto-sessions/{id}/stream`) HTTP-мидлварью не
перехватывается; он защищён неугадываемым `session_id` (а чтобы стартовать
сессию, токен нужен).

## Когда нужен настоящий мультипользователь

Если потребуется, чтобы несколько человек пользовались **одновременно** и
независимо, понадобится регистрация + изоляция сессий/миссий по пользователю
(отдельные неймспейсы данных, очередь). Это отдельный крупный пласт работы,
несоразмерный текущему этапу; здесь сознательно не реализован.
